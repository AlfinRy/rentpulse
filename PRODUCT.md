# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users
Rental seekers comparing rooms or apartments across cities. This is the working audience from the conversation; no user research has been conducted.

## Product Purpose
RentPulse watches rental pages, scores their fit against saved criteria, and sends match digests. A saved search is called a Pulse.

## Operating Context
Convex All Gas hackathon prototype. The user requested implementation with design skills and incremental GitHub pushes. Repo: https://github.com/AlfinRy/rentpulse. Existing stack: React, TypeScript, Vite, Convex, Firecrawl and AgentMail; OpenAI scoring.

## Capabilities and Constraints
The backend is an unverified draft, not a deployed service. Convex login, generated APIs, authentication, API credentials, and end-to-end verification remain prerequisites for a public live service. Never expose private criteria or emails through unauthenticated functions. No automatic spending or outbound email in the frontend demonstration.

## Brand Commitments
RentPulse is the current project/repository name. The user wanted a name understandable beyond Indonesia. No user-pinned colors or typography.

## Evidence on Hand
Local scaffold and draft backend only. No real inventory, photography, customers, performance benchmarks, successful sends, or verified availability. All invented listings must be labeled as examples, including their prices and match scores.

## Product Principles
- Explain why a listing fits and what remains unknown.
- Keep example and live data clearly separate.
- Surface trade-offs rather than hiding them behind a score.
- Small meaningful commits; push each completed milestone.

## Open Decisions / Working Assumptions
User instructed us to proceed. English interface, desktop-first responsive comparison workspace, and a self-contained sample mode are implementation assumptions, not findings from research. Authentication provider and production data-source permissions remain undecided.
